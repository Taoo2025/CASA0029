================================================================================
London PTAL Accessibility Map - 启动与故障排查指南
================================================================================

【快速启动】
1. 双击 "启动地图.bat" 或 "启动地图.ps1"
2. 等待服务器启动（会有 "Serving" 等消息）
3. 浏览器自动打开地图

【问题排查】

[问题 1] 页面显示 "Failed to fetch"
────────────────────────────────────────────────────────────────────────────

可能原因与解决方案：

A) 服务器未运行或未正确启动
   → 检查方法：
     - PowerShell 运行：诊断工具.ps1
     - 或手动访问 http://localhost:8080/ 看是否显示目录列表
   
   → 解决方法：
     1. 关闭任何旧的地图服务器窗口
     2. 重新运行 启动地图.bat
     3. 等待至少 5 秒让服务器完全启动
     4. 刷新浏览器 (Ctrl+F5)

B) 数据文件缺失
   → 检查方法：
     1. 打开 File Explorer，进入地图文件夹
     2. 检查是否存在以下文件/文件夹：
        - bus_routes_detailed.json
        - route_lines.geojson
        - London_LSOA_Centroids.geojson
        - DATA/ 文件夹
     3. 运行诊断工具.ps1 查看详细检查结果
   
   → 解决方法：
     - 如果缺少重要文件，重新下载或复制完整的地图文件夹

C) 端口 8080 被占用
   → 检查方法：
     PowerShell 运行：netstat -ano | Select-String ":8080"
   
   → 解决方法：
     1. 关闭其他占用端口 8080 的程序（如旧的地图服务）
     2. 使用启动地图.ps1，它会自动检测并处理

D) CORS 或网络问题
   → 检查方法：
     1. 打开浏览器开发者工具 (F12 → Console)
     2. 查看红色错误消息
     3. 运行诊断工具.ps1
   
   → 解决方法：
     1. 清除浏览器缓存 (Ctrl+Shift+Del)
     2. 关闭浏览器，重新打开
     3. 确保使用 http://localhost:8080 而非 http://127.0.0.1:8080

[问题 2] 浏览器显示 "无法连接" 或 "Connection refused"
────────────────────────────────────────────────────────────────────────────

原因：服务器根本没有启动

解决方法：
1. 确保 Python 已安装 (运行 PowerShell: python --version)
2. 确保在正确的文件夹中 (包含 London_PTAL_Accessibility_Map.html)
3. 运行 启动地图.ps1 而不是 .bat (更好的诊断)
4. 如果 PowerShell 脚本显示错误，按照错误消息解决

[问题 3] 页面加载但地图没有显示数据
────────────────────────────────────────────────────────────────────────────

可能原因：
- 某些可选数据文件缺失（这是正常的，地图仍能工作）
- Mapbox API 问题（网络连接问题）

解决方法：
1. 打开浏览器开发者工具 (F12)
2. 查看 Console 标签中的警告或错误
3. 查看 Network 标签，找出哪些请求失败
4. 如果是 "data_manifest_osm_network.json" 等文件，这是可选的
5. 地图应该仍能显示基础的 PTAL 数据

【使用工具】

启动地图.bat
─────────────
推荐给Windows用户。简单快速的启动脚本。

启动地图.ps1
─────────────
高级诊断版本。在出问题时提供更详细的错误信息。
运行方式：
  1. 打开 PowerShell
  2. 运行：Set-ExecutionPolicy -Scope Process -ExecutionPolicy RemoteSigned
  3. 运行：.\启动地图.ps1

诊断工具.ps1
────────────
用于检查和诊断问题。
运行方式：
  1. 打开 PowerShell
  2. 进入地图文件夹
  3. 运行：.\诊断工具.ps1

【深度调试】

1. 浏览器控制台调试 (F12 → Console)
   查看所有加载的文件和任何 JavaScript 错误

2. 网络标签调试 (F12 → Network)
   查看每个 HTTP 请求的状态
   - 绿色 = 成功 (200)
   - 红色 = 失败 (404, 500, 等)
   - 灰色 = 被阻止或 CORS 错误

3. 检查服务器日志
   查看启动服务器的窗口，看是否有错误消息

【常见错误信息解释】

"Cannot fetch from file://"
→ 必须通过 HTTP 协议访问，不能直接打开 HTML 文件

"HTTP 404 Not Found"
→ 某个数据文件在服务器上找不到，检查文件是否存在

"HTTP 401/403 Unauthorized/Forbidden"
→ 权限问题，检查文件权限或重启服务器

"Network error" 或 "Failed to fetch"
→ 一般网络或 CORS 问题，检查服务器是否运行、浏览器网络是否正常

【文件结构】

必需文件：
  ├── London_PTAL_Accessibility_Map.html (主程序)
  ├── serve_range.py (服务器)
  └── bus_routes_detailed.json (基础数据)

可选数据文件（缺少时地图仍能工作，但功能受限）：
  ├── DATA/
  │   ├── LSOA_simplified.geojson (LSOA 边界数据)
  │   └── PTAL_2023_Grid_100mx100m_Data.geojson (100m 网格数据)
  ├── route_lines.geojson (公交线路)
  ├── London_LSOA_Centroids.geojson (LSOA 中心点)
  └── grid_to_lsoa.json (网格到LSOA映射)

可选分析数据（用于高级功能）：
  ├── data_chunks_osm_network/ (步行时间数据)
  ├── grid_ai_chunks_osm_network/ (网格AI分析)
  ├── data_manifest_osm_network.json
  └── grid_ai_manifest_osm_network.json
